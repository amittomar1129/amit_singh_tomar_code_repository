1. HTTP Client API (Standardized):

Before Java 11, developers used HttpURLConnection or third-party libraries like Apache HttpClient
Java 11 introduced modern HTTP client.

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class Main {
    public static void main(String[] args)
            throws Exception {

        HttpClient client =
                HttpClient.newHttpClient();

        HttpRequest request =
                HttpRequest.newBuilder()
                        .uri(new URI("https://example.com"))
                        .GET()
                        .build();

        HttpResponse<String> response =
                client.send(
                        request,
                        HttpResponse.BodyHandlers.ofString()
                );

        System.out.println(response.body());
    }
}

Advantages:
HTTP/2 support - Faster communication
Async support - Non-blocking

client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
      .thenApply(HttpResponse::body)
      .thenAccept(System.out::println);

2. Structured Concurrency (Preview): One of the most important modern concurrency features.
Structured Concurrency is a concept of dividing a task into subtasks and processing them concurrently.
Structured concurrency introduces parent-child lifecycle for concurrent tasks, enabling failure propagation,
 cancellation, and scoped task ownership, making concurrent code easier to reason about and safer.

Purpose:
Manage concurrent tasks with:
lifecycle ownership
cancellation propagation
failure handling

Unstructured Concurrency:

Invoice createInvoice(int orderId, int customerId, String language)
    throws InterruptedException, ExecutionException {
  Future<Order> orderFuture =
      executor.submit(() -> orderService.getOrder(orderId));

  Future<Customer> customerFuture =
      executor.submit(() -> customerService.getCustomer(customerId));

  Future<InvoiceTemplate> invoiceTemplateFuture =
      executor.submit(() -> invoiceTemplateService.getTemplate(language));

  Order order = orderFuture.get();
  Customer customer = customerFuture.get();
  InvoiceTemplate invoiceTemplate = invoiceTemplateFuture.get();

  return Invoice.generate(order, customer, invoiceTemplate);
}

If an error occurs in one subtask – how can we cancel the others? In the example above, if loadOrderFromOrderService(…) fails,
 then orderFuture.get() throws an exception, the createInvoice(…) method ends, and we may have two orphan threads still running.

How can we abort the subtasks when the parent task (“create invoice”) is cancelled – or when the complete application is shut down?

How can we – in an alternative use case – cancel the remaining subtasks when only the result of a single subtask is needed?


Structured Concurrency:
Forking: You split a task into concurrent subtasks using scope.fork().
Joining: You wait for subtasks to finish with scope.join().
Result Handling: You can then process the results or handle exceptions collectively.

ShutdownOnFailure: If any subtask fails, it triggers a "short circuit," cancelling all other still-running subtasks.
ShutdownOnSuccess: Useful for "race" scenarios; once the first subtask succeeds, it cancels the remaining ones and returns that result.

StructuredTaskScope.ShutdownOnSuccess()
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {

    var user = scope.fork(() -> getUser());

    var orders = scope.fork(() -> getOrders());

    scope.join();

    scope.throwIfFailed();

    System.out.println(user.get());
}

Parent-child task ownership
Automatic cancellation
Easier debugging

Excellent for:

parallel API calls
request orchestration
microservices aggregation

Designed especially for virtual threads, immutable shared context.

Core Idea

use: Scoped immutable context


eg.    static final ScopedValue<String> USER = ScopedValue.newInstance();

Good Use Cases:

import java.lang.ScopedValue;
import java.util.concurrent.StructuredTaskScope;

public class Demo {

    static final ScopedValue<String> TRACE_ID =
            ScopedValue.newInstance();

    static void serviceCall() {
        System.out.println(
                "Trace: " + TRACE_ID.get()
        );
    }

    public static void main(String[] args)
            throws Exception {

        ScopedValue.where(
                TRACE_ID,
                "REQ-123"
        ).run(() -> {

            try (var scope =
                         new StructuredTaskScope
                                 .ShutdownOnFailure()) {

                scope.fork(Demo::serviceCall);

                scope.fork(Demo::serviceCall);

                scope.join();
            } catch (Exception e) {
                e.printStackTrace();
            }
        });
    }
}

Output:

Trace: REQ-123
Trace: REQ-123

9. Vector API: Perform multiple computations simultaneously.
Vector API allows Java programs to perform multiple mathematical operations simultaneously using CPU
vector instructions (SIMD - Single Instruction Multiple Data).

Example

Instead of: one operation at a time (Scalar Processing)
1+1
2+2
3+3
4+4

CPU can do: vector operations
[1,2,3,4]
+
[1,2,3,4]
=
[2,4,6,8] in one operation. Huge speedup.

Scalar Processing:
for (int i = 0; i < n; i++) {
    c[i] = a[i] + b[i];
}

Vector Processing:
import jdk.incubator.vector.*;

public class Demo {

    static final VectorSpecies<Integer> SPECIES = IntVector.SPECIES_PREFERRED;

    public static void main(String[] args) {

        int[] a = {1,2,3,4};
        int[] b = {5,6,7,8};
        int[] c = new int[4];

        int i = 0;

        for (; i < SPECIES.length(); i += SPECIES.length()) {

            var va = IntVector.fromArray(SPECIES, a, i);
            var vb = IntVector.fromArray(SPECIES, b, i);

            var vc = va.add(vb);

            vc.intoArray(c, i);
        }

        for (int x : c) {
            System.out.println(x);
        }
    }
}



10. Generational ZGC: Major JVM enhancement.
Generational ZGC is one of the biggest JVM garbage collection improvements. Ultra-low-latency garbage collector.
It enhances Z Garbage Collector (ZGC) by adding Generational Collection.

Generational ZGC is a low-latency garbage collector that separates objects into young and old generations
to improve throughput, memory efficiency, and GC performance while maintaining extremely low pause times.


First understand G1 Garbage Collector. It is a Current default collector in modern Java.
The Garbage-First (G1) Garbage Collector is a server-style algorithm designed for multi-processor machines with large memories.

Core Mechanism: Region-Based Layout:
Unlike traditional collectors that divide the heap into fixed, contiguous generational sections (Eden, Survivor, Tenured),
G1 partitions the entire heap into approximately 2,048 equal-sized regions (ranging from 1MB to 32MB).

G1 tracks the amount of "live" data in each region. When it performs a collection,
it prioritizes regions that are mostly full of garbage, hence the name "Garbage-First".



Generational ZGC (Z Garbage Collector) is an advanced version of the ZGC garbage collector introduced in Java 21
 (JEP 439) to improve application performance by maintaining the Weak Generational Hypothesis.
 This hypothesis states that most objects die young; by focusing on the "Young Generation" more frequently,
 the collector can reclaim memory more efficiently using fewer CPU resources.

 Ultra-Low Latency: Maintains sub-millisecond pause times regardless of heap size.
 Separated Generations: Divides the heap into a Young Generation (for recently allocated objects) and an Old Generation
  (for objects that survive several GC cycles).

How it Works:
Colored Pointers: Uses metadata bits directly in object pointers to track object states without stopping application threads.
Concurrency: All major tasks—marking, relocating, and compacting memory—happen concurrently while the application continues to run.
Adaptive Memory Management: Dynamically resizes generations and scales the number of GC threads based on the current workload.
